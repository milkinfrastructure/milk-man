# Security Policy

## Reporting a vulnerability

Do not report security vulnerabilities through public Issues, Discussions, or
pull requests.

Email `hello@milkinfrastructure.com` with the subject `Milk Man security`.
GitHub private vulnerability reporting is not yet enabled for this repository.

Include the following when possible:

- The affected version or commit
- The affected component and environment
- Reproduction steps or a minimal proof of concept
- The expected and observed impact
- Any known mitigations

Do not include real API keys, tokens, personal data, or credentials. Use
redacted or disposable test values and ask before sending sensitive evidence.

## Upstream Headlong defects

Report an independently reproducible defect in retained Headlong code to its
upstream maintainers and notify Milk privately when it affects a Milk release.
Milk remains responsible for assessing and patching its distribution.

## What to Expect

Maintainers will assess the report, determine its scope, and coordinate
remediation and disclosure when appropriate. Security fixes are prepared
against the default branch and released on a schedule chosen by the
maintainers. We do not guarantee fixes for older versions.

For a non-sensitive defect, use a focused public pull request with a minimal
reproduction if a fix is available.
